# دليل النسخ الاحتياطي واستعادة البيانات - Learning Tree Connect

## نظرة عامة

يوضح هذا الدليل استراتيجية النسخ الاحتياطي الشاملة لمنصة Learning Tree Connect، ويغطي قاعدة البيانات والملفات المرفوعة والكود المصدري. الهدف هو ضمان إمكانية استعادة النظام بالكامل في حال حدوث أي خلل أو فقدان للبيانات.

---

## مكونات النظام التي تحتاج نسخاً احتياطياً

| المكون | نوع البيانات | الأهمية | طريقة النسخ |
|--------|-------------|---------|------------|
| قاعدة البيانات (TiDB) | بيانات المستخدمين والأطفال والتقارير والفواتير | حرجة | تصدير SQL |
| تخزين الملفات (S3) | صور التقارير اليومية والمرفقات | عالية | مُدار تلقائياً |
| الكود المصدري | ملفات المشروع والإعدادات | عالية | نقاط التفتيش + GitHub |

## النسخ الاحتياطي لقاعدة البيانات

### الطريقة الأولى: التصدير اليدوي من واجهة الإدارة

واجهة قاعدة البيانات في لوحة الإدارة (Management UI > Database) توفر إمكانية عرض البيانات وتصديرها مباشرة. يمكنك استخدامها لتصدير الجداول المهمة بشكل دوري.

### الطريقة الثانية: تصدير SQL عبر الاتصال المباشر

يمكنك الحصول على معلومات الاتصال بقاعدة البيانات من إعدادات Database في واجهة الإدارة (الزر في أسفل يسار الشاشة). معلومات الاتصال تشمل:

| المعلومة | الموقع |
|----------|--------|
| المضيف (Host) | إعدادات Database |
| المنفذ (Port) | إعدادات Database |
| اسم المستخدم | إعدادات Database |
| كلمة المرور | إعدادات Database |
| اسم قاعدة البيانات | إعدادات Database |

> **ملاحظة مهمة:** يجب تفعيل SSL عند الاتصال بقاعدة البيانات من خارج المنصة.

### أمر التصدير باستخدام mysqldump:

```bash
mysqldump \
  --host=<HOST> \
  --port=<PORT> \
  --user=<USER> \
  --password=<PASSWORD> \
  --ssl-mode=REQUIRED \
  --single-transaction \
  --routines \
  --triggers \
  <DATABASE_NAME> > backup_$(date +%Y%m%d_%H%M%S).sql
```

### تصدير جداول محددة:

```bash
# تصدير بيانات المستخدمين فقط
mysqldump --host=<HOST> --port=<PORT> --user=<USER> \
  --password=<PASSWORD> --ssl-mode=REQUIRED \
  <DATABASE_NAME> users children > users_backup.sql

# تصدير البيانات المالية فقط
mysqldump --host=<HOST> --port=<PORT> --user=<USER> \
  --password=<PASSWORD> --ssl-mode=REQUIRED \
  <DATABASE_NAME> invoices loyalty_points loyalty_transactions > finance_backup.sql
```

## النسخ الاحتياطي للكود المصدري

### نقاط التفتيش (Checkpoints)

المنصة تحتفظ بسجل كامل لنقاط التفتيش المحفوظة. يمكنك الوصول إليها من:

- **واجهة الإدارة > القائمة (⋯) > Version history**
- كل نقطة تفتيش تحتوي على لقطة كاملة للكود في تلك اللحظة
- يمكن الرجوع لأي نقطة سابقة عبر زر Rollback

### التصدير إلى GitHub

لحفظ نسخة خارجية من الكود:

1. افتح واجهة الإدارة
2. اذهب إلى **Settings > GitHub**
3. اربط حساب GitHub الخاص بك
4. اختر اسم المستودع والمالك
5. اضغط **Export**

هذا ينشئ مستودع GitHub جديد يحتوي على كامل الكود المصدري.

### تحميل الملفات كـ ZIP

1. افتح واجهة الإدارة
2. اضغط على القائمة (⋯) في أعلى اليمين
3. اختر **Download as ZIP**
4. احفظ الملف في مكان آمن

## النسخ الاحتياطي لملفات التخزين (S3)

ملفات التخزين (صور التقارير اليومية والمرفقات) تُدار تلقائياً عبر خدمة S3 المدمجة في المنصة. هذه الملفات:

- مخزنة بشكل متكرر عبر مناطق متعددة (redundant storage)
- محمية من الفقدان على مستوى البنية التحتية
- لا تحتاج نسخاً احتياطياً يدوياً في الظروف العادية

> **ملاحظة:** إذا كنت بحاجة لنسخة محلية من الملفات المرفوعة، يمكنك الوصول إليها عبر روابط `/manus-storage/` المخزنة في قاعدة البيانات.

## استعادة البيانات

### استعادة قاعدة البيانات من نسخة SQL:

```bash
mysql \
  --host=<HOST> \
  --port=<PORT> \
  --user=<USER> \
  --password=<PASSWORD> \
  --ssl-mode=REQUIRED \
  <DATABASE_NAME> < backup_20260619_120000.sql
```

> **تحذير:** الاستعادة تستبدل البيانات الحالية. تأكد من أخذ نسخة من الحالة الحالية قبل الاستعادة.

### استعادة الكود من نقطة تفتيش:

1. افتح واجهة الإدارة
2. اذهب إلى **القائمة (⋯) > Version history**
3. اختر النسخة المطلوبة
4. اضغط **Rollback**

### استعادة الكود من GitHub:

إذا كنت قد صدّرت الكود إلى GitHub مسبقاً، يمكنك استنساخ المستودع واستخدامه كمرجع لإعادة البناء.

## أفضل الممارسات

**التخزين الآمن للنسخ الاحتياطية:** يجب تخزين النسخ الاحتياطية في مكان منفصل عن النظام الأصلي. يُنصح باستخدام خدمة تخزين سحابية مختلفة (مثل Google Drive أو Dropbox) أو قرص صلب خارجي مشفر.

**التشفير:** جميع النسخ الاحتياطية التي تحتوي على بيانات شخصية (أسماء الأطفال، أرقام الهواتف، البيانات المالية) يجب تشفيرها قبل التخزين. يمكن استخدام أدوات مثل `gpg` لتشفير ملفات SQL:

```bash
gpg --symmetric --cipher-algo AES256 backup_20260619.sql
```

**الاختبار الدوري:** يجب اختبار عملية الاستعادة بشكل دوري (مرة كل 3 أشهر على الأقل) للتأكد من أن النسخ الاحتياطية صالحة وأن عملية الاستعادة تعمل بشكل صحيح.

**التوثيق:** احتفظ بسجل لجميع عمليات النسخ الاحتياطي والاستعادة، يشمل التاريخ والوقت والشخص المسؤول والنتيجة.
